# Repository Maintenance Agent · HJ10

一个从教学原型逐步发展的仓库维护 Agent 项目。目前完成 **MVP 0：看懂执行闭环**。

这版用预设脚本提出操作，真实执行代码读取、AST 符号检索、跨文件补丁和 Python 测试；运行后生成可逐步浏览的中文离线报告。**没有接入语言模型，不产生模型能力或方法提升的实验结论。**

## 立即运行

需要 Python 3.10+，仅使用标准库，无需安装依赖、下载模型或启动服务。

```sh
python mvp/run_demo.py --open
```

Windows PowerShell 可使用包装脚本，它会寻找已有 Python（包括本机 Codex 提供的运行时）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-demo.ps1 -OpenReport
```

每次运行建立新的 `mvp/runs/demo-时间-随机后缀/`，不修改原始教学仓库。打开其中的 `report.html`，点击步骤或使用上一／下一步查看过程。浏览器报告完全离线，按钮用于查看已执行的记录，不会再次修改文件。

## 演示内容

任务：让一个小型 Python 下载请求支持超时配置。CLI 优先于配置，未提供时保持 5；最终选中值须为正的有限整数或浮点数（拒绝 bool 和字符串）；仅校验选中值，保留 URL 和默认请求行为。这里构造请求字典，不发起真实网络请求，也不演示重试实现。

```text
仓库地图 → 符号查找 → 读代码与公开测试 → 计划 → 起点测试
  → 修改 config.py 和 client.py → 测试发现零值/bool 问题
  → 局部修复 → 重测 → 结束 → 独立需求与回归评测
```

在当前固定教学任务上，可见测试应依次为 **1/8 → 5/8 → 8/8**；最终独立需求测试 **7/7**、回归 **3/3**。这是专门设计来解释失败恢复的样例，不是对陌生仓库的泛化成绩。

可以降低预算，观察未完成状态：

```sh
python mvp/run_demo.py --max-steps 3
```

预算耗尽返回非零退出码，仍保存轨迹和独立评测，不伪装成成功。

测试结果按方法计数；跳过和预期失败不计为验收通过。测试加载失败、执行超时与环境故障分别记录，加载失败或超时的具体原因需要查看日志，可能来自代码，也可能来自环境。

## 从哪里读代码

| 文件 | 关注的问题 |
| --- | --- |
| `mvp/run_demo.py` | 复制任务工作区、运行流程、最后独立验收 |
| `mvp/hj10/agent.py` | 模型/策略怎样与工具交替执行，何时停止 |
| `mvp/hj10/policy.py` | 预设教学决策；下一阶段替换为模型适配器 |
| `mvp/hj10/tools.py` | 文件与编辑边界、AST 定义、文本候选引用、测试调用 |
| `mvp/test_runner.py` | 新进程运行 unittest，返回结构化测试结果 |
| `mvp/hj10/report.py` / `report_template.html` | 将实际轨迹呈现为离线报告 |
| `mvp/fixtures/timeout_demo/` | 保留初始缺陷的三文件教学仓库及公开测试 |
| `mvp/evaluation/hidden_timeout_tests.py` | 只供独立评测器使用的示范验收检查 |

建议先读 `agent.py`，再对应报告看每一次 `Action → observation`，最后看工具实现。源码注释中的 `Policy.next_action(history)` 是下一阶段接入真实模型的位置。

## 运行产物

- `workspace/`：本轮修改后的仓库副本。
- `task.txt`：本轮任务说明。
- `trajectory.jsonl`：每一步的意图、工具参数、实际反馈与耗时。
- `final.patch`：初始代码到最终代码的统一 diff。
- `summary.json`：停止状态、预算、评测和耗时；模型调用为 0，token 为 null。
- `report.html`：可直接打开的中文轨迹浏览器。

运行目录默认不提交到 Git。原始 fixture 里的测试会失败，这是任务的起点；维护系统自身的检查请运行：

```sh
python -B -m unittest discover -s mvp/tests -v
```

## 已有边界与下一步

当前仅支持这个受信任的教学仓库。工具按文件名单限制读取和编辑，禁止改测试；测试在独立 Python 进程中执行。这些边界**不构成操作系统级沙箱**，不要将本版直接用于运行任意外部仓库。

评测源码不进入任务工作区，也不通过工具或反馈交给策略；它随仓库公开，目的是展示独立验证的组织方式，不能作为正式研究中的保密测试集。教学策略事先知道样例修法，也不能用于评估检索质量。

后续按小步叠加：

1. 用真实小模型实现同一个决策接口，保留当前工具与轨迹格式。
2. 在少量开发任务上比较普通 Agent 与人工提供相关修改前代码，判断模型/上下文瓶颈。
3. 根据结果只选择一个核心机制改进，先考虑上下文选择；固定模型和预算做对照与消融。
4. 建立独立开发/测试任务、隔离执行及多次实验，再讨论成功率与回归收益。

具体模型、语言范围和任务来源尚未确定。课程评分细则、投入、完整硬件与预算仍待确认。
